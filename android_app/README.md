# ಪದLab Android

Flutter/Dart implementation of the PHFI Kannada Word Reading Assessment. This is the Android-native implementation track; the existing Next.js PWA remains preserved at the repository root as a design and behaviour reference.

## Status

**Foundation preview only — not approved for participant use.**

This milestone establishes the Flutter app structure, assessor-to-child preview navigation, protocol constants, deterministic session allocation logic, initial SQLite schema, and automated quality checks.

It intentionally does not bundle the supplied stimulus lists, play assessment audio, record participant trials, or claim field readiness. The uploaded non-word CSV currently contains 193 rows while the working allocation calls for 194. The requirements also call for native Kannada review and written approval before items are loaded.

## Requirements baseline

- Android tablet application written in Flutter/Dart.
- Android 8.0 (API 26) or newer; actual tablet model must be verified.
- Landscape-only, full-screen child assessment; keep the display awake during a session.
- Fully offline: bundled item bank, recorded Kannada audio and fonts; SQLite data stays on-device.
- Six sessions, provisionally 45 real words + 32 non-words = 77 scored items per session.
- Five practice items are provisionally additional to the 77 scored items; this interpretation needs protocol confirmation.
- Signed release APK and assessor installation guide.

The current allocation plan uses 270 real words and 192 of the intended 194 non-words across the six sessions; two non-words remain in reserve. The currently uploaded CSV has only 193 non-word rows. See [the working allocation note](../docs/protocol/working-allocation-v1.md).

## Local setup

Install the Flutter stable SDK and Android SDK (Android Studio is the recommended way to install the SDK and emulator).

From this directory:

```bash
flutter create . --platforms=android --org org.phfi.cdlr --project-name padalab_android --no-pub
flutter pub get
dart format lib test
flutter analyze
flutter test
flutter run
```

The `android/` host project is generated by `flutter create` with the installed Flutter SDK. This keeps the Gradle wrapper and Android host files aligned with the toolchain.

## Project structure

```
lib/
  app/                 App composition and design system
  core/config/         Explicit study protocol constants
  data/database/       SQLite schema and persistence boundary
  features/
    assessor/          Assessor-only participant/session entry
    child/             Isolated child-facing preview
    assessment/
      domain/          Item, allocation and trial models
test/                  Protocol and allocation tests
```

## Safety and research guardrails

- Do not use this preview with children.
- Do not put participant data, names, trial exports, approved item-bank files, voice recordings or signing keys in Git.
- Do not load candidate non-words until native-language review and written study approval are documented.
- Do not use browser speech synthesis or network-hosted audio for field sessions.
- Trial persistence must be awaited before the assessment engine advances to another stimulus.
- A failed local write must keep the current item visible.
- No analytics, crash telemetry, remote logging or cloud sync may be introduced.
- CI success is not evidence of offline, reaction-time, audio, data-integrity or field-pilot readiness.
